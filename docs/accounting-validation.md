## 已修复

- 同批扣款原先只保留最后一条通知。基线生产构建在真实 Chromium 页面中输入两条指令，出现“事由2”、没有“事由1”，确认覆盖。
- 每笔扣款保存独立回执（指令 ID、孩子、金额、事由、当笔结余），按时间逐条确认；未读与已读状态跨刷新、重新连接保留。
- 使用持久回执与旧账单共同去重，独立核算家长扣款对累计支出的贡献，防止重放时统计重复增加。
- 暂扣按惩罚编号保存多份契约；冻结、赎回使用确定性账单键。同步合并后按契约重建金额，消除双设备对同一契约的重复入账。
- 到期检查先于赎回，截止日期当天有效，次日没收；关闭自动惩罚也会检查到期。返还比例按契约固定，提示显示实际返还金额。
- 结算前写入完整恢复日志，再发布账单、回执、指令状态。IndexedDB 完成前保留日志；刷新启动先恢复。存储配额不足时不确认新账目。
- 云端同步取消旧的 React 防抖写入，避免同步后的状态被旧计时器覆盖。
- 转盘固定本次惩罚编号，动画结束再次检查远端完成日志；清理待办时只清理对应编号。暂扣时护盾消耗与账目一起保存。
- 兼容旧单契约、旧扣款账单，备份导入导出含回执，删除孩子时清理对应数据。

## 测试

```sh
npm ci
npx playwright install --with-deps chromium webkit
npm run test:all
```

`npm test`：21 项领域/存储测试。覆盖批量通知金额、事由、逐笔余额，重复指令、重连、刷新、单向确认合并、孩子隔离、授权、非法金额、旧账单、余额归零；连续暂扣、双设备赎回、并发不同转盘金额的收敛、期限边界、部分返还、旧契约；IndexedDB 恢复、快速连续提交、配额失败和 localStorage 降级。

`npm run test:e2e`：7 个真实 App 场景，在 Chromium 和 WebKit 各执行一次，共 14 项。包括逐条确认与中途刷新、旧 pending 重放、两个独立浏览器上下文赎回并调用实际同步合并逻辑、逾期不返还、成员/授权/礼物隔离、真实转盘连续两次暂扣后刷新再赎回、动画期间远端核销。

`npm run build`：全部页面生产构建；`git diff --check`：格式检查。

当前环境的 Playwright 默认 Chromium 下载镜像失败，使用临时安装的 Chromium 153 二进制，通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定；WebKit 使用 Playwright 1.57 的 WebKit 2227。仓库不依赖临时二进制。WebKit 使用 iPad 视口/触摸模拟，**不是实体 iPad 10 或 iPadOS Safari**。

E2E 阻止外部网络，节假日接口降级日志属预期；同步测试直接调用应用的合并函数，未访问生产云数据、未做生产服务器并发压力测试。测试不等于全程序所有功能已穷尽验证。

## 兼容边界

- 需相关设备都升级。旧客户端仍会生成旧赎回键，不能据此声称混用旧版本具有全局 exactly-once 保证。
- 当前保证是持久化去重与更新客户端合并收敛，不是服务端原子交易协议；同时打开多个同源标签页也不是本次验证的场景。
- 旧版已覆盖丢失的契约、缺失的历史逐笔结余无法凭空还原；旧扣款回执明确标注“当前结余（历史扣款）”。
- 恢复日志占用 localStorage，账本极大或存储受限时可能拒绝新账目，需要释放空间；不会用仅内存确认绕过存储失败。
