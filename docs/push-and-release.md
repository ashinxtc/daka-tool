# 推送接入与整体发布验收

本批承接 #11。2026-10-17 已按用户授权执行生产后端迁移；当前发布状态以文末记录为准，历史批次验收记录不能替代正式设备配对验收。

## 已实现的推送边界

- 订阅、取消、测试、同步通知均通过同步服务确认同家庭 main/parent 身份。安全订阅按设备保存；不保存设备 token。安全家庭旧匿名订阅停止发送，配对后重新开启通知。
- 发送前复查接收设备有效性；撤销、到期、恢复管理员导致的旧设备失效会阻止新发送。已交给浏览器推送服务的消息无法召回。
- 同步 Worker 仅提供 `/services/push` 专用只读投影。调用需要推送服务 HMAC 签名，绑定方法、路径、完整查询和一分钟时间窗；不能用签名读普通快照、修改业务或管理设备。一分钟内只读重试允许。
- 投影只包含指定孩子的任务 ID、频率、开始日和打卡存在标记，不包含任务标题、笔记、余额、其他孩子、密码或 API 密钥。推送 Worker 删除直接读取家庭 KV 的绑定，无匿名或旧 KV 回退。
- 订阅目标限制为 Apple、Google、Mozilla、Windows 推送地址，禁止重定向。手动 cron/VAPID 调试需要独立运营密钥。列表支持分页。
- 前端只在服务端返回明确成功回执后显示开启成功；凭据只送固定推送端点，网络错误不伪报成功。北京时间 8/16/20 点对应 UTC cron 0/8/12 点，不新增客户端定时器。

## 私密配置的实际位置

检查代码后需修正早期报告的一处泛化描述：当前 Web Push 定时任务需要任务/打卡数据，并不需要业务快照里的 API key。VAPID 私钥本来就由 Worker secret 注入。本批不为它新增可读取全部家庭秘密的接口。

| 配置 | 保存位置 | 使用者 |
| --- | --- | --- |
| PUSH_SERVICE_SECRET | 同步、推送 Worker 各自的 secret，值相同 | 专用提醒投影签名/验签 |
| VAPID_PRIVATE_KEY_HEX | 推送 Worker secret | 加密推送；不更换既有值以免订阅失效 |
| OPERATIONS_TOKEN | 推送/兑换各自独立的 Worker secret | 运营调试与维护；不得共用家庭管理密钥 |
| AUTH_BOOTSTRAP_SECRET | 同步 Worker secret及受控签发环境 | 家庭激活/恢复 |
| 企业微信服务秘密 | 原企业微信 Worker secrets | 原企业微信服务；需要单独核查正在使用的接口 |
| 本机 AI key、报告等设置 | 本机存储，不进入安全家庭快照 | 原本机功能；新设备独立配置 |

历史 KV/备份中已经存在的秘密并不会因投影隐藏而消失。必须先保留受控恢复副本，再轮换暴露过的密钥，核对所有历史副本的保留/清理策略。不能自动删除用户旧备份。企业微信独立接口、外部脚本等如果实际使用，也必须登记并验收，不能用 Web Push 的测试替代它们。

## 已提供的迁移核对工具

`node scripts/migration-audit.mjs frozen-before.json protected-after.json legacy-orders.json offline-orders.json`

输入为冻结并核对后的原始业务快照对象（app_* 字符串值）和两个明确的订单数组。工具只读；比较业务字段，检查秘密清除、未结清订单、重复/无效订单 ID；输出键名和数量，不打印值或凭据。失败退出码 2。缺少清单不能当作空清单。

成功只意味着这些导出文件一致，不证明 KV 已收敛、票据已经真实兑付、设备已升级或云环境已验收。必须先核对真实票据再填写已核销/取消状态，不能为了通过校验修改导出状态。工具不导入、核销或删除任何订单。

## 整体发布顺序与硬门槛

1. 获取 Cloudflare 受控部署权限，确认账户、SQLite DO 支持、线上 Worker 版本、路由、服务绑定、现有私密配置的存在性及备份位置。不要把密钥明文贴进聊天或提交仓库。
2. 创建独立测试 Worker/KV/DO/推送订阅存储；配置中不得复用生产 namespace ID。部署同步、兑换、推送及配套服务绑定、secrets。测试域名前端不得指向生产同步地址。
3. 在独立环境运行现有回归覆盖的双端修改、扣款通知、兑换竞争/断网、设备撤销/恢复，并验证真实测试设备订阅与推送到达、配置更新、停用和回退。当前本地 Miniflare 不替代 Cloudflare 部署验收。
4. 枚举实际家庭、使用中的主/家长设备及外部集成；核对旧 pending/离线票据，冻结基准并备份。使用核对工具验证迁移前后数据。每个旧设备明确升级/停用，不接受旧协议写入回退。
5. 统一发布仍需有序执行：兼容前端 → 旧写入冻结/基准核对 → 配套同步/兑换/推送 Worker → active → 家庭激活及配对 → 兑换配置确认 → 启用兑换。`AUTH_MODE=enforced` 是全局开关，必须覆盖所有现存家庭，不能拿单个测试家庭通过代替全量准备。
6. #7–本批按依赖顺序合并；每次更新 base 后复核最终集成 CI，确保 main 自动部署与 Worker 发布窗口协调。启用后保留 active 配置；需要暂停时使用 paused，不能恢复旧 KV 写入。正式网站上线后核对版本及核心操作。

独立测试构建、配置与手机端部署步骤见 [staging-deployment.md](staging-deployment.md)。

## 浮动兑换规则兼容修正

用户确认继续保留生产版浮动汇率玩法。安全兑换现在由同步服务通过 EXCHANGE_MARKET_SERVICE 的公开行情接口取价，沿用基准 USD 汇率、每元宝基础分值、日间波动放大与最低值公式。服务绑定只指向同环境的兑换 Worker，不转发设备凭据。管理员初次读取设置时建议沿用旧快照中的基准与放大参数，保存确认后由服务端持有；客户端不能自行改变结算参数。

新报价有效五分钟，并绑定设备；申请携带报价编号及对应整数微元汇率。参数变更清除未提交报价。订单保存申请金额，回执重试与核销不依赖最新行情、不重算金额。行情不可用暂停生成新报价，但不影响已有订单的查询、回执重试及核销。汇率统一按百万分之一元量化，人民币按分结算。旧预览固定定价配置仍兼容；新的管理员界面只引导配置浮动规则，生产迁移必须逐家庭确认参数，不得直接启用默认固定价格。

新增回归覆盖旧公式涨跌及最低值、管理员权限、报价伪造/失效、行情变化及故障后的回执重试、原金额核销及只扣一次款。浏览器兑换验收改用真实隔离服务的浮动报价。生产部署仍须完成全部家庭激活和迁移核对，本修正不代表生产已上线。
