# 数据可靠性修复

基线：`c33e67d`（PR #6 合并后的 main）。本批覆盖本地保存、启动、备份恢复、密码读取及相关同步门禁。

## 数据约定

- 沿用 `daka_app_db/app_keyval`、数据库版本 1 和现有业务键名。业务值仍保存为字符串。
- `useStickyState` 注册的是已解码的 React 值，统一使用 `JSON.stringify` 保存，包括字符串、false、0 和空字符串。
- 旧版直接写入的字符串配置仍可读取，密码读取同时兼容 JSON 字符串、旧明文字符串与空值。
- 启动状态明确区分 loading、ready、error；主程序仅在 ready 后挂载。慢读取不再在 1.5 秒后放行默认数据，8 秒后提供重试入口。
- 读取失败或既有 IndexedDB 暂时不可访问时，保留数据并显示重试，不当成首次安装。
- 云端同步在数据未就绪、恢复期间、已知本地保存失败时暂缓。恢复会改变本地 epoch，恢复前发起的同步响应不能再应用到恢复后的数据。

## 保存与迁移

1. 旧数据迁移必须完成事务并读回核验，才设置迁移标记、清理旧副本。
2. 失败的批量写入保留在待写队列；显示可重试的保存状态。
3. `visibilitychange(hidden)`、`pagehide` 和 `beforeunload` 汇总 React 待保存值，并先写入同步恢复日志，再尝试完成 IndexedDB 写入。
4. 恢复日志复用 `_accounting_journal_v1`；沿用 `entries` 字段，增加可选的 `deletedKeys`。正在写入的批次也计入日志。
5. 下次启动先回放未完成日志，再开放主程序。迁移过程不能提前清除尚未回放的账务日志。
6. 普通写盘仍使用批量防抖；空闲回调增加最长等待时间，不引入常驻轮询。

## 备份与恢复

- 设置面板与首次使用页共享 `backup.js`，导出会包含 React 尚未到达防抖时间的修改。
- 沿用 2.0 导出格式及旧别名，接受 1.0、2.0 备份、全量快照和原始 `app_*` 键。先校验全部条目，再开始写入；对成员、任务、金额、指令和回执增加结构检查。
- 保持原有覆盖语义：覆盖文件包含的项目，保留文件未包含的当前项目。界面确认文案明确说明这一点。
- IndexedDB 模式：单个事务同时保存恢复前快照、导入值、版本号和镜像修复标记。事务失败时自动保留原数据，提交后才更新内存并刷新页面。
- 镜像修复标记保证在事务提交后、localStorage 镜像更新前关闭页面，下次启动仍以新数据为准。
- localStorage 降级模式：写入恢复日志后才修改数据，失败或中断时回滚；若恢复副本无法写入则拒绝恢复。恢复日志未成功回滚时阻止进入主程序。
- 保留一份恢复前快照，设置中的备份面板可下载。它位于本地内部键，不参加家庭同步。

## 验证与发布

执行 `npm test`、`npm run test:e2e`、`npm run build`。GitHub Actions 对 PR 和 main 自动运行三项检查；WebKit 软件环境的两个 WebGL 专项保留原有跳过策略，其他 WebKit 用例必须通过。

新增覆盖：迁移写失败与重试、慢启动、读取失败、挂起保存、JSON 字符串、账务日志与迁移交叉恢复、删除回放、恢复事务同步失败与异步中止、镜像修复中断、localStorage 降级恢复、错误备份、两个真实导入入口、导出未落盘修改及核销密码。

本地验证（2026-10-17）：

- 单元测试 53/53 通过，生产构建通过，`git diff --check` 通过。
- 最终浏览器套件共 60 项：57 项通过、2 项为原有 WebKit WebGL 跳过项、1 项原有字阵测试发生 WebKit `Target crashed` 进程退出。
- 对该字阵用例使用三个独立测试 worker 连续复测，3/3 通过；此前完整一轮也通过。尚未稳定复现该进程崩溃，保留记录，不把它写成一次无异常的全套通过。
- 本批 7 个新增浏览器场景在 Chromium 与 WebKit 共 14/14 通过；其中包括重复同步后改回原值的保存，以及旧浏览器 FileReader 导入路径。
- 浏览器测试使用隔离的模拟家庭，主程序场景阻断外部请求，未向线上家庭写入测试数据。

该批不改 Worker 协议、三档能耗策略或业务计价规则。服务端身份验证、云端并发控制和零花钱核销授权仍属于后续批次。

## 回退与边界

- 本批无需数据库升级或云端数据迁移。发布前保留可下载的家庭备份；代码回退只回退本批前端提交。
- 回退前先在本版本完成保存，确认没有保存/恢复错误，避免旧版本遇到未处理的新删除或恢复标记。旧版本只认识恢复日志的 `entries`，不认识新增标记。
- 恢复前快照用于恢复本地误导入；不会自动撤销已经同步到其他设备的数据，也不是服务端多版本备份。
- 浏览器在任意时刻被强制终止、磁盘永久不可写、存储被系统整体清除，都不能保证尚未完成持久化的普通修改不丢失。本批增加挂起日志和失败提示，关键账务继续先持久化再发布。
- 并行标签页与跨设备写入的全局事务保证由后续同步一致性批次处理。本批不宣称解决服务端竞争。
- 自动化浏览器验证不等同于真实 iPad 的功耗或系统进程终止测试。
