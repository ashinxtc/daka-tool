# 服务端身份与权限基础（草稿，不能单独启用）

基于 PR #8 的事务同步分支。**本批只交付同步服务权限基础及其回归测试，不是完成全部安全整改，也不是上线迁移。** `AUTH_MODE` 默认 `legacy`；主程序、家长端、兑换和推送尚未接入凭据，禁止把生产环境切到 `enforced`。没有部署 Worker、修改线上配置、签发真实家庭凭据或读取真实家庭快照。

## 为什么先单独验证这一层

现有家长绑定依赖本机标记、快照里的密码及配对信息。这些内容不能继续作为可信身份来源。只加客户端密码框或隐藏按钮，无法阻止直接调用 API；只先开启服务端鉴权，又会使尚未升级的客户端断开。因此先建立并验证服务端权限契约，再让所有调用者一起接入，最后在隔离环境演练迁移。

本次不改视觉/能耗档位、iPhone 安全区、扣款计算规则、3D 展厅，也不新增后台定时器。

## 权限边界

| 身份 | 同步读取 | 同步写入 | 设备管理 |
| --- | --- | --- | --- |
| 未授权 | 无；仅可读取迁移状态 | 无 | 持有效激活凭证认领，或兑换有效邀请 |
| owner 家庭管理员 | 无普通快照权限 | 无普通快照权限 | 签发邀请、查看设备、撤销设备 |
| main 家庭主设备 | 当前、备份、时间戳 | 可信家庭业务快照；不可上传秘密或伪造授权名单 | 仅撤销自己 |
| parent 家长设备 | 当前、备份、时间戳 | 追加本人合法指令/留言；不可改余额、任务、其他人的记录或已有指令内容 | 仅撤销自己 |

`main` 是目前架构下的**可信业务写入端**，不是服务端事件账本：有主设备凭据的人仍能修改业务余额等数据，本批不能证明每一项奖励都由可信服务端计算。它不能签发身份或提升为 owner。家长已经通过授权提交的指令属于家庭业务数据，不会因撤销设备而被服务端删除。

家长可新增扣款、红包、额外转盘、邪恶转盘，必须匹配服务端签发的设备 ID、称谓和真实孩子，且为 pending 状态；扣款/红包金额须为正安全整数。不能改写既有指令，不能删 pending 指令或其他人的记录。可删除自己的已处理历史或自己的留言。留言必须绑定设备，文本限 32 字、存续不超过 24 小时，不能伪造点赞。

## 身份接口与生命周期

所有接口都使用 `?code=家庭同步码` 路由到该家庭的 Durable Object；同步码不再是 protected 家庭的访问凭据。凭据只从 `Authorization: Bearer …` 接收，不从 Cookie、URL 或快照接收。响应不缓存。

- `GET /auth/mode`：返回 required/initialized，不返回家庭业务数据。
- `GET /auth/check`：校验当前设备，返回 ID、角色、称谓、到期时间；供后续客户端和服务绑定接入。
- `POST /auth/claim`：body `{voucher, token}`。仅 active + enforced 可认领。服务运营者使用 `AUTH_BOOTSTRAP_SECRET`（至少 32 字符，应使用密码学安全随机值）在受控管理环境签发一小时 HMAC-SHA256 凭证，绑定家庭、用途和随机 nonce。实现函数 `mintActivation` 当前用于隔离测试；本批没有面向最终用户的激活工具或界面。
- `POST /auth/invite`：owner 提交 `{role: 'main'|'parent', label}`，签发十分钟、单次可用邀请。不能邀请 owner。
- `POST /auth/redeem`：`{invite, token}`。客户端先生成并安全保留 256-bit 随机设备 token，再兑换；服务端只保存哈希。并发兑换只接受一台设备。相同邀请/token 的丢失响应重试可在一日内返回原身份，不会多建设备。
- `GET /auth/devices`：仅 owner；只返回公开设备字段，不返回 token 或哈希。
- `POST /auth/revoke`：`{id}`；owner 可撤销 main/parent，设备可撤销自己。撤销持久化；旧 token、旧邀请重放、旧保存回执不能恢复权限。

普通设备凭据有效期 180 天，需要重新配对；owner 凭据无自动到期，不能放在孩子主程序的普通配置里。最多 100 台有效设备、128 条设备记录，最多 32 个未到期邀请；达到历史上限需管理员核对后恢复/重新配对。恢复凭证使用 `purpose='recover'`，替换 owner 并使旧设备及邀请全部失效，保留业务数据。丢失管理密钥需要管理员带外确认身份，不能用曾经暴露在快照里的旧密码自动找回。

本批不保存明文设备 token，也不记录授权请求体。凭证生成端和设备端仍须保护明文；同源 XSS 或设备失窃可窃取 Bearer，随机 token 不替代前端 XSS 防护与设备安全。

## 同步、秘密隔离和回退

- 当前、备份、时间戳和 POST 均检查身份；先鉴权，再读取/迁移旧数据。写入事务内再次检查撤销状态。幂等保存回执额外绑定原设备身份。
- protected 快照隐藏现有密码、API key、Webhook、回调 token/AES key、报告配置以及旧配对 token；授权名单由服务端生成，不能从客户端覆盖。版本表里的秘密配置项也被移除。受保护上传若带秘密配置，明确拒绝，而不是默默丢弃用户设置。
- 当前 key 分类涵盖现有配置，**不是任意嵌套 JSON 的通用秘密扫描器**。新增配置必须更新分类测试；不能把密钥藏进普通业务键。旧 KV 和旧内部快照仍可能含历史秘密，需要管理员按保留策略清理，并轮换已经暴露的第三方密钥。
- 授权名单变化、家长凭据到期会在下一次合法同步访问中推进 revision/ts，让轮询能发现变化。未变化的 `/ts` 只读版本头和小型身份状态，不读取/重写大快照。更新与业务写入使用同一个事务，旧版本写入返回 409。
- 激活后的家庭有持久化锁。即使配置退回 legacy 也不能取消鉴权；退到 readonly 不会暴露旧 KV，而是对合法读返回 503。不存在 Durable Object 绑定也不绕回 KV。未激活的 legacy 家庭保留原来的只读迁移和 active 同步行为。
- `AUTH_MODE` 拼写错误返回配置错误，不悄悄当作 legacy。完全回滚到不包含鉴权逻辑的旧 Worker、删除 DO 或旁路读取旧 KV **不在代码能够阻止的范围内**，必须由部署权限和流程防止。

## 启用前必须一同完成的下一批工作

后续客户端批次已接入第 1–3 项的管理/配对与主、家长端同步，范围和验证见 [设备配对与客户端接入](device-pairing-client.md)。以下仍作为完整发布核对清单；第 4–6 项仍是生产开启阻断项。

兑换后续批次实现了第 4 项的隔离预览路由、客户端接入及原子结算，见 [兑换权限与原子结算](exchange-transactions.md)。旧订单核对和混合客户端停用方案仍需在迁移演练中完成，不能将代码完成等同于生产已切换。

以下不是可选优化，是发布阻断项：

1. **管理和配对界面**：激活、保管 owner 密钥、限时邀请、撤销、恢复；邀请放 URL fragment 并立即清理，不能进查询参数/日志/Referrer。兑换前持久化配对意图以支持刷新和响应丢失；普通设备凭据不得进入 `app_*` 同步、导出备份或 URL。
2. **全部客户端调用链**：主程序首次同步、手动/自动同步、时间戳、备份恢复、家长端读写均携带正确角色凭据。401/403 明确暂停云端操作，保留本机数据；不得自动降级匿名读取或显示假成功。升级后要验证刷新、切家庭、重新连接及过期重配。
3. **配置和授权名单**：本机秘密仍保留，但 protected 同步不采集、不合并它们；新设备需要独立配置私密集成。服务端授权名单不能再与旧本机名单做并集合并。尤其当前客户端“名单为空则兼容放行”的逻辑，在 `securityVersion:1` 下必须改为拒绝，而不是让最后一台家长撤销后反而放行旧指令。家长留言新增 operatorDeviceId，历史清理遵守本人的记录范围。
4. **兑换全链路**：兑换 Worker 通过服务绑定校验同一家庭和角色，覆盖申请、列表、单笔查询、取消、限额、核销；不能仅凭订单 ID 或四位核销码。扫码页携带家庭上下文，家长设备授权后核销；受保护模式禁用“网络失败自动生成离线票”和“本地密码校验就先扣款、后台忽略核销失败”。全局物价维护使用运营权限，不得借用家庭 owner。另需解决 KV 核销/取消和额度并发的事务边界；仅鉴权不解决并发结算。
5. **推送及其他服务**：现有推送读取依赖同步快照中的私密配置。需独立的服务身份、最小读取权限和服务端私密配置存储；不能继续匿名拉快照，也不能给推送滥发每个家庭的 owner 权限。
6. **迁移与验收**：新旧客户端混用、所有秘密来源/返回范围、撤销后空名单、邀请抢兑、设备到期、恢复、跨家庭订单、重复核销、取消并发、断网刷新都通过后，再在独立 Worker/KV 和测试家庭演练。先备份，轮换旧秘密，确认所有客户端升级，才制定生产开启窗口。`enforced` 当前是全服务开关，未激活家庭也会被拒绝，不能直接全量打开。

## 验证范围

`tests/family-access.test.js` 使用隔离的 Miniflare/workerd 和 SQLite Durable Object 测试：未授权访问、跨家庭 token、激活签名/有效期/中文同步码、邀请抢兑与丢失回执、权限提升、秘密和备份脱敏、家长越权、撤销竞态、请求重放、管理员恢复、轮询版本传播、重启持久化和配置回退。到期边界另有确定性的状态测试。

同时运行现有 `npm test`、Chromium/WebKit 浏览器回归、`npm run build`、`git diff --check`。浏览器回归验证的是 **legacy 兼容行为**；不能用它宣称尚未接入的安全配对/兑换 UI 已完成端到端验证，也不测量真实 iPad 功耗。

本批应保持草稿。依次评审/合入前置 #7、#8，完成上述接入与迁移门槛后，再决定安全批次的最终发布；不要因为基础测试通过就开启生产鉴权。
