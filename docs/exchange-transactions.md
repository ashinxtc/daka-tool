# 兑换权限与原子结算：隔离迁移预览

承接设备配对批次。默认 `AUTH_MODE=legacy`、`EXCHANGE_MODE=off`，不部署、不自动迁移旧订单。必须先完成推送与迁移验收，才能决定生产开启窗口。

## 本批处理的完整操作

- 安全家庭的申请、列表、单笔查询、取消、核销、汇率及限额走同一家庭的 SQLite Durable Object。申请限 main，核销限 parent，修改汇率/限额限 owner；订单 ID 和四位码均不能代替设备身份。
- 权限在事务开始时再次校验。申请使用持久化的 operationId；同一身份、同一内容重试返回原订单，不能换金额。每日一次、每周额度（未过期 pending + verified）、余额检查与订单创建同事务。取消/过期释放待处理额度；已核销记录不按旧 KV 的短 TTL 删除。
- 核销检查最新云端余额，订单变为 verified 与写入 `孩子-EXCHANGE-订单ID` 扣款在同一事务提交，并推进同步版本。核销/取消竞态只有一个终态；核销响应丢失后重试不重复扣款。普通快照上传不得新增、修改或删除兑换扣款条目。
- 恢复旧备份、首次接入或选择同步冲突的本机版本时，兑换扣款仍采用服务端记录，防止本机遗漏/伪造账目造成永久同步失败或显示错误结余。其他账目保持原有合并规则。
- 余额算法由主程序和服务端共用，保留旧打卡、数组打卡、投资倍率、完成奖励、历史账目语义。这里的余额以同步主程序的业务资料为基础，**不意味着已将所有任务奖励、商店消费等迁到服务端，也不提供完整防作弊账本**。离线尚未上传的收入不能用于云端兑换。
- 保留原钱庄界面及财商图表。安全模式结算采用家庭管理员确认的固定汇率（百万分之一元精度），金额以整数计算后四舍五入到分；市场图表仅供参考。首次必须由 owner 读取并保存配置，不自动套用旧本机浮动汇率。已提交订单锁定金额与汇率，后续配置变化不追改旧订单。
- 申请前保存本机意图；断网不生成离线单，不报告核销/撤销成功。查询恢复原订单后确认对应意图，避免已取消订单卡住新申请。保护模式当面核销转入家长授权页，不再用平板本地密码先扣款。
- 安全二维码只携带家庭与订单 ID；扫码页从服务端读取孩子、金额和状态，忽略链接中的金额/孩子名。家长需在最终使用浏览器配对；配对后重新扫码。刷新可以确认响应丢失前已完成的核销。

## 旧 API 与部署顺序

兑换 Worker 新增 `SYNC_SERVICE -> daka-sync` 服务绑定。对所有订单/限额操作，先查询该家庭的保护状态。旧票据只有订单 ID 时，仅内部读取其所属家庭作权限路由；显式家庭与旧票据所属家庭不符直接拒绝。受保护家庭转发到安全事务路由，缺绑定、绑定异常或权限响应无效均失败关闭，不能回落旧 KV。

未保护家庭仍走原兑换流程；因此**本批并未宣称生产 legacy 的 KV 并发及离线核销问题已经消失**。这些行为只在完成安全迁移并启用预览路径的家庭中被替换。

全局物价初始化/更新、手动刷新市场数据要求独立 `OPERATIONS_TOKEN`（至少 32 字符，通过环境秘密注入）。不能使用家庭 owner token 维护全局数据；现有无凭据维护调用将被拒绝。定时服务更新保留。

部署前后必须保证兑换 Worker 的权限路由与同步 Worker 配套，不能只更新前端或只打开 AUTH_MODE。保持新路由，即使关闭 EXCHANGE_MODE 也只暂停交易，不会恢复旧 KV 核销。移除服务绑定或回滚到不带权限检查的旧 Worker 不属于本代码可防止的部署风险。

## 隔离验收与剩余门槛

1. 在独立 Worker/KV/DO 环境启用 active + enforced + preview，配置服务绑定。测试管理设备、孩子平板、家长手机分别配对。
2. 旧 pending/离线订单逐笔核对、取消或结清；保存旧账和核销记录。不得将旧 KV 订单无校验地自动导入，不能让同一票据同时从两套系统核销。
3. owner 确认汇率/限额后保存；演练申请响应丢失、扫码、核销响应丢失、断网取消、余额被其他操作用掉、重复同步、跨家庭与撤销设备。
4. 对仍离线的旧客户端制定停用/升级步骤，并完成推送服务身份与私密配置迁移后，才允许安排生产切换。

单家庭暂限 1000 条订单，达到上限停止新申请而非删除历史/幂等凭据；后续需实现经过核对的归档流程。单笔查询直接读一条订单，避免待核销轮询反复扫描全部历史。本批没有新增持续轮询或动画，也没有声称测得真实 iPad 功耗改善。

回归入口：`tests/exchange.test.js`（真实 Miniflare 并发/持久化与权限、失效边界）、`tests/e2e/exchange.spec.js`（真实主程序和核销页），以及现有全部单元/Chromium/WebKit/构建检查。
